# AR4 MK5 control stack

Kinematics, trajectory planning and two interchangeable backends for an
Annin Robotics AR4 MK5 with the SG1 gripper. The same motion code drives the
MuJoCo simulator and the real arm.

```
motion/     FK, IK, Jacobian, Cartesian lines, pen drawing   (pure Python)
backends/   sim.py (MuJoCo)  |  hw.py (Teensy over USB serial)
tools/      demo.py (chess pick-and-place), draw.py, touch_page.py
models/     ar4.xml; meshes/ is generated by tools/populate_meshes.py
tests/      pytest; hardware tests run against tests/fake_teensy.py
```

Setup, from `ar4/`, on Python 3.12 (the pins in `simulation/requirements.txt`
need it, and Annin's compiled FK oracle ships for 3.11/3.12):

```
pip install -r requirements.txt
python tools/setup_env.py      # reference checkouts beside the repo + meshes
python -m pytest -q            # 90 tests, none should skip
```

`setup_env.py` clones [Annin-Robotics/ar4_ros_driver](https://github.com/Annin-Robotics/ar4_ros_driver)
(MK5 meshes, Teensy firmware) and [Annin-Robotics/ar4-hmi](https://github.com/Annin-Robotics/ar4-hmi)
(the FK oracle) at pinned commits into the directory the repo sits in, and
leaves any existing checkout alone. CI (`.github/workflows/tests.yml`) runs the
same steps.

## Drawing

```
python tools/draw.py art.svg                     # plan it, write art.preview.svg
python tools/draw.py art.svg --sim               # watch it in MuJoCo
python tools/touch_page.py --port COM5           # measure the real page -> page.json
python tools/draw.py art.svg --page page.json --port COM5 --gripper-port COM6 --grip
```

- **Look at the preview first.** It is the pen path computed back from the
  planned joints, over the input, with pen-up travel dashed.
- **The page is measured, not assumed.** `touch_page.py` jogs the pen onto the
  paper at three or more points and fits a plane. A 6-axis arm's idea of "the
  table" is typically millimetres off across a page.
- **The pen leans ~15° toward the robot.** With it vertical, the wrist passes
  within a degree of its J5 singularity somewhere on an A4 page at every yaw;
  `choose_pen` picks the smallest lean that keeps J5 at least 20° clear.
- **Use a compliant pen holder** (spring or foam). The pen is driven 1 mm below
  the touched surface to guarantee contact (`--press`, 0 for a rigid mount).
- **SVG outlines only.** Fills are ignored and text must be converted to paths
  first (Inkscape: Path → Object to Path).

## Hardware

`backends/hw.py` speaks the Teensy firmware from
[Annin-Robotics/ar4_ros_driver](https://github.com/Annin-Robotics/ar4_ros_driver)
(2.1.0, model `mk5`). ycheng517's upstream reports the same version but does not
accept `mk5`. The stock firmware limits every joint to 60°/s and 30°/s², so
trajectories are slowed to fit before they are sent.

**It has not driven a real arm yet.** The first powered session is
`tools/bringup.py`, e-stop in hand:

```
python tools/bringup.py --rehearse                      # practise, nothing attached
python tools/bringup.py --port COM5 --gripper-port COM6
```

It connects, homes, checks every joint reads ~0 at park (a wrong offset), jogs
each joint 10° while telling you where the fingertip should go (a wrong sign),
measures tracking lag on a short line at several gains, and tests the gripper.
It stops at the first failure and writes `bringup-<date>.json` with the exact
edits to `backends/hw.py` it calls for.
